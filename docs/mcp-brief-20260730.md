## Problem

AI agents frequently pick the wrong tool or take extra steps because MCP tool descriptions are poorly written.  

2026 research shows:
- 97% of analyzed tool descriptions contain at least one "smell"
- Common smells: unstated purpose, missing usage guidelines, opaque parameters, vague verbs
- Accuracy of weaker models drops below 90% when more than 10-15 tools are visible

This directly hurts reliability of any product that uses MCP (including Prevalid's AI accountability layer).

## Solution

An MCP server that other agents (or developers) can call to:

1. Audit a single tool description → score 0-100 + list of smells + suggestions
2. Rewrite a weak description into a best-practice version
3. Audit a full tool list → overcrowding warning + ranked quality
4. Return the current best-practice checklist

## Type

**Type A — Computation heavy / zero external API cost**

All logic is pure TypeScript rules + heuristics. No paid APIs, no scraping, no keys required. High margin.

## Target users

- MCP server authors (before they publish)
- AI agent developers who care about reliability
- Teams building control / accountability layers for AI (Prevalid-aligned)

## Competitive landscape

No dedicated "tool description auditor" MCP server found in major marketplaces at research time. Closest are general linters or documentation generators, none focused on LLM tool-selection accuracy.
